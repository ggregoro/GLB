# GLB profile: developer
#
# Aimed at someone newer to development work who wants a solid, complete
# kit without researching every tool choice themselves — a "here's what's
# good" value prop applied to dev tooling instead of desktop apps. Not
# aimed at someone who already knows exactly what they want (they'd
# install it themselves anyway). See CLAUDE.md (2026-08-07) for the
# audience decision and the forks below.
#
# Package names are resolved per-distro before being passed to your
# package manager (apt/dnf/pacman/zypper). See _GLB_PACKAGE_OVERRIDES
# in lib/package.sh for the few that aren't the same everywhere.

# Shell/prompt foundation — same unified bash/zsh/fish + Starship setup
# as the default profile (see dotfiles/).
git
curl
zsh
fish
fzf
eza
bat
zoxide
btop
bash-completion    # loads glb's completion file - see lib/completions.sh
unzip              # needed for the font extras.txt entry

# Terminal editor — same as default. A real gap found testing on
# CachyOS (2026-08-10): developer originally shipped only Fresh (via
# extras.txt) as its editor, so `nvim` didn't run at all here even
# though it's one of default's packages. Added neovim alongside Fresh
# rather than replacing it, matching default's own pairing.
neovim

# Containers — Podman chosen over Docker: daemonless/rootless fits a
# newcomer better as a safe default (no root daemon running out of the
# box), and fits GLB's philosophy over Docker's more familiar name.
podman

# C/C++ build toolchain. Deliberately just gcc+make rather than chasing
# a single meta-package name across distros (apt's build-essential,
# dnf's "Development Tools" group, pacman's base-devel group, zypper's
# devel_basis pattern) — none of those resolve as a single `<mgr>
# install -y <name>` the way glb_install_package works, so a real
# meta-package equivalent would need a new install mechanism, not just
# a packages.txt entry. Revisit if that's ever built.
gcc
make

jq

# GitHub CLI — package name is "gh" on apt (Debian 12+/recent Ubuntu)/
# dnf/zypper, but "github-cli" on pacman (see _GLB_PACKAGE_OVERRIDES).
# Not empirically verified on every distro yet — flag for real-machine
# testing.
gh

ncdu

# TUI git client and terminal markdown renderer. Not as long-established
# as the rest of this list (fzf/ripgrep/etc.) - package availability
# across all four managers isn't empirically verified yet, same caveat
# as gh above. Flag for real-machine testing.
#
# lazygit has a confirmed real gap on Fedora/dnf (2026-08-10): it isn't
# in Fedora's official repos at all, only via a third-party COPR
# (atim/lazygit) that has had real build failures on recent Fedora
# releases and signature-verification issues - not a reliable install
# target. Its own project also has no single-URL curl-installer script
# (unlike lazydocker), so it doesn't fit GLB's existing `curl` extras
# method either. Left as a known gap rather than building new
# tarball-extraction extras infrastructure for one package on one
# distro - same call as the fastfetch-on-Mint/Pop!_OS gap in
# default/packages.txt. Fedora users hit this via the normal
# manual-step pause/skip prompt and can move on.
lazygit
glow
