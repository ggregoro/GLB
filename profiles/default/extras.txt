# GLB profile: default — extras (installs outside apt/dnf/pacman/zypper)
#
# Format: <method> <name> <spec>
#   curl <name> <url>       - runs `curl -fsSL <url> | bash`. <name> is
#                              checked with `command -v` to detect an
#                              existing install.
#   flatpak <name> <app-id> - ensures the flathub remote, then
#                              `flatpak install -y flathub <app-id>`.
#                              <name> is just a display label; <app-id>
#                              is checked via `flatpak info`.
#   font <name> <zip-url>   - downloads a Nerd Fonts release zip,
#                              extracts it into
#                              ~/.local/share/fonts/<name>, then runs
#                              `fc-cache -f`. <name> becomes the install
#                              directory, so no spaces. Requires unzip
#                              (see packages.txt).
#   snap <name> <confinement> - `sudo snap install <name>
#                              [--<confinement>]`. <confinement> is
#                              typically "classic" or left blank for
#                              strict; checked via `snap list <name>`.
#                              Requires snapd (see packages.txt).
#   github-release <name> <owner/repo> <asset>
#                            - downloads
#                              github.com/<owner/repo>/releases/latest/
#                              download/<asset>, verifies <asset>.sha256
#                              if the release publishes one, unpacks any
#                              .tar.*/.zip (or takes a raw binary), and
#                              installs the <name> binary into
#                              ~/.local/bin. <asset> is a literal
#                              filename. <name> is checked with
#                              `command -v`. Like snap, a
#                              _GLB_EXTRA_NATIVE_OVERRIDES entry routes
#                              this to a real package on managers that
#                              have one.
#   github-release-tree <name> <owner/repo> <asset>
#                            - same download/verify as github-release,
#                              but extracts the WHOLE archive into
#                              ~/.local (stripping its one top-level
#                              directory) instead of pulling out a
#                              single <name> binary. For tools that ship
#                              a relative bin/lib/share tree their
#                              binary needs alongside it to find its own
#                              data files - a plain github-release grab
#                              of just the binary would leave those
#                              behind. Tar archives only. <name> is
#                              checked at ~/.local/bin/<name>. Same
#                              _GLB_EXTRA_NATIVE_OVERRIDES routing as
#                              github-release.
#
# Blank lines and lines starting with '#' are ignored, same as
# packages.txt.

# Code editor - default's dotfiles already wire up editbash/
# editstarship aliases that look for this on $PATH.
curl    fresh     https://raw.githubusercontent.com/sinelaw/fresh/refs/heads/master/scripts/install.sh

# Nerd Font - required for `eza --icons` (all three shells' ls/ll/la/l
# aliases). Every machine tested before the Linux Mint test VM already
# had this font pre-installed by hand, which masked the fact glb
# restore never actually installed it itself - a real fresh-install gap.
font    jetbrains-mono-nerd-font    https://github.com/ryanoasis/nerd-fonts/releases/latest/download/JetBrainsMono.zip

# File manager alternative to ranger (kept, not replaced) - stronger
# plugin support (image previews, the git-status plugin configured in
# dotfiles/.config/yazi/). Was `snap yazi classic` until 2026-09-12:
# every real cross-distro bug this project has ever hit traced back to
# snap (atuin's broken sandbox, fastfetch missing from apt's index, the
# /snap/bin PATH-shadowing bug, Fedora's missing /snap symlink for
# classic confinement) - moved off it wherever a real alternative
# exists, per Greg's call. yazi publishes real GitHub release binaries
# (confirmed live), so it moves the same way atuin/fastfetch/neovim
# already did. The archive is flat (yazi + ya + docs, no bin/lib/share
# tree to preserve), so plain `github-release` is the right method, not
# `github-release-tree` - `find`'s `-perm -u+x` filter picks the real
# `yazi` executable over the non-exec `yazi.bash`/`yazi.fish`/etc.
# completion scripts with the same name, same as fastfetch's own
# same-name-non-exec-file case. On pacman this still routes to the real
# native `yazi` pacman package (see _GLB_EXTRA_NATIVE_OVERRIDES in
# lib/extras.sh) - unchanged, confirmed 2026-08-16. zypper previously
# had no path at all here (no snapd, no native package) - now gets the
# same upstream binary apt does, closing that gap as a side effect.
# Asset is the x86_64 glibc build; yazi publishes no per-asset .sha256
# (same as fastfetch/neovim), so this download isn't checksum-verified.
github-release    yazi    sxyazi/yazi    yazi-x86_64-unknown-linux-gnu.zip

# Ghostty - a GPU-accelerated terminal emulator that speaks the Kitty
# graphics protocol, so yazi (above) renders real images in it instead
# of falling back to chafa's Unicode-block art. This is a DELIBERATE,
# narrowly-scoped exception to GLB's "no GUI applications, terminal
# emulators included" rule (docs/PHILOSOPHY.md) - it earns its place
# only as the graphics-capable host yazi's image preview needs where a
# distro's default terminal provides none. COSMIC Terminal (a common Pop!_OS default;
# pop-os/cosmic-term#438 still open) supports no inline
# image protocol at all, and its bundled/apt chafa is 1.14.0 while
# yazi >= 26.x needs chafa >= 1.16 for `--probe` - so on cosmic-term
# there is no working image preview without a terminal that draws the
# images itself. Ghostty does not become the default terminal; it's
# launched on demand via the yazi.desktop launcher shipped in this
# profile's dotfiles/.local/share/applications/ (bare `ghostty ... -e
# yazi`, so it resolves whether Ghostty is a snap or a native package).
# Binding a key to that command is a per-desktop-environment manual
# step - COSMIC/KDE/GNOME each do custom shortcuts differently, none
# portably, so GLB documents it rather than automating three fragile
# code paths (see docs/design/ghostty-yazi.md).
#
# Per-distro routing via the same _GLB_EXTRA_NATIVE_OVERRIDES mechanism
# yazi used to use before it moved to github-release (2026-09-12) -
# Ghostty stays on snap since it has no generic Linux binary release to
# move to instead (links dynamically against system GTK4):
#   pacman  -> native `ghostty` (Arch `extra` repo) - confirmed
#   zypper  -> native `ghostty` (openSUSE repo-oss) - confirmed
#   apt     -> snap (not in Debian/Ubuntu/Pop!_OS/Mint apt index) -
#              needs `_glb_ensure_snap_dir`'s /snap symlink on distros
#              missing it (Fedora, confirmed 2026-09-12); Mint also
#              blocks snapd itself by policy (nosnap.pref)
#   dnf     -> snap (Fedora ships Ghostty only via COPR, not the
#              official repos - GLB doesn't chase non-default repos,
#              same call as lazygit on dnf)
snap    ghostty   classic

# atuin - searchable, SQLite-backed shell history that replaces Ctrl-R
# in bash/zsh/fish (init wired into all three shell dotfiles, guarded
# on `command -v atuin`, `--disable-up-arrow` so plain Up stays
# per-session history). Not in apt's index on Debian/Ubuntu/Pop!_OS,
# so `default`'s primary (apt) target pulls the upstream static binary
# from the latest GitHub release into ~/.local/bin.
#
# NOT the atuin snap: it's strictly confined and can't create
# ~/.config/atuin or ~/.local/share/atuin, so `atuin init` errors on
# every shell start; `snap run` strips the ATUIN_CONFIG_DIR /
# ATUIN_DATA_DIR overrides that would move them; and `scripts` /
# `atuin import auto` don't work through the sandbox. (See the retired
# claude/atuin-snap-config-dir branch for the redirect attempt that
# doesn't survive `snap run`.)
#
# On pacman/dnf/zypper this routes to the real native `atuin` package
# instead (see _GLB_EXTRA_NATIVE_OVERRIDES in lib/extras.sh). dnf/zypper
# native availability is believed-good but not yet confirmed on a real
# VM - same "verify next cross-distro pass" caveat as the original
# firefox:zypper / libreoffice:pacman overrides. The GitHub-release
# asset is the x86_64 glibc build; arm64 or musl-only hosts need the
# asset name changed here.
github-release    atuin    atuinsh/atuin    atuin-x86_64-unknown-linux-gnu.tar.gz

# fastfetch - system-info banner (pairs with cpufetch in packages.txt).
# Not in apt's index on `default`'s fresh-VM targets (Pop!_OS 24.04,
# Linux Mint 22.x - "no installation candidate", confirmed twice), where
# a bare packages.txt line forced a manual-step pause on every restore.
# This pulls the upstream release tarball (usr/bin/fastfetch) into
# ~/.local/bin. dnf/pacman/zypper route to the native `fastfetch`
# package via _GLB_EXTRA_NATIVE_OVERRIDES and never touch this.
#
# Asset is the amd64 glibc build; fastfetch also ships
# `-polyfilled` variants for older glibc and aarch64/armv7l/etc. -
# change the asset name for those. fastfetch publishes no per-asset
# .sha256, so unlike atuin this download isn't checksum-verified (the
# method just skips that step when the sidecar is absent).
github-release    fastfetch    fastfetch-cli/fastfetch    fastfetch-linux-amd64.tar.gz

# neovim (LazyVim's editor, config vendored in dotfiles/.config/nvim) —
# apt's `neovim` (0.9.5) is too old for LazyVim (needs >= 0.11.2), hit
# for real on Greg's E7450 (2026-09-06, again 2026-09-11 after a
# reinstall): a bare packages.txt entry silently installs a version
# that refuses to load with "requires 0.11.2". Uses `github-release-tree`,
# not plain `github-release`: nvim's binary looks up its own runtime
# files (syntax/ftplugin/colorscheme data, Treesitter parsers) at a
# path relative to itself, so it needs its release's lib/ and share/
# directories extracted alongside bin/nvim in ~/.local, not just the
# bare binary — confirmed the single-binary method breaks this
# ("E484: Can't open file .../syntax/syntax.vim", "E185: Cannot find
# color scheme"). dnf/pacman route to the native `neovim` package
# instead via _GLB_EXTRA_NATIVE_OVERRIDES (both confirmed current,
# >= 0.11.2); zypper isn't verified either way yet, so openSUSE also
# gets the upstream tarball for now rather than risk the same
# too-old-for-LazyVim bug this exists to fix. Asset is the x86_64
# glibc build; neovim publishes no per-asset .sha256 (same as
# fastfetch above), so this download isn't checksum-verified either.
github-release-tree    nvim    neovim/neovim    nvim-linux-x86_64.tar.gz
