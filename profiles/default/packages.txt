# snapd - needed for the snap extras.txt entry below (yazi). Confirmed
# in apt's index (Pop!_OS/Debian/Ubuntu). Not in Arch/pacman's official
# repos at all (AUR-only) - but this no longer matters on pacman
# specifically: yazi has a real native pacman package (`extra` repo),
# so the snap extras.txt entry below routes through it directly there
# (see _GLB_SNAP_NATIVE_OVERRIDES in lib/extras.sh) and snapd itself is
# skipped outright on pacman via _GLB_PACKAGE_SKIP in lib/package.sh -
# confirmed 2026-08-16, no more manual-step pause on Arch-family
# machines. Confirmed real gap on zypper too (2026-08-13, openSUSE
# Tumbleweed VM, real restore of the server profile): `zypper info
# snapd` reports "package 'snapd' not found" in the default repos, and
# zypper has no native yazi package either (no OBS repo), so snap/yazi
# still don't install there - same known-gap treatment as lazygit on
# Fedora/dnf rather than chasing a non-default repo. dnf unverified.
#
# Linux Mint (apt) is its own distinct case, confirmed 2026-08-25 on a
# fresh Mint VM: `apt install snapd` fails with "has no installation
# candidate" even though the package is genuinely in Mint's index -
# Mint ships /etc/apt/preferences.d/nosnap.pref, pinning snapd to
# priority -1 by deliberate policy (not a repo gap like pacman/zypper
# above). Not auto-skipped like snapd:pacman, since the user has a
# real fix (delete that file) rather than no path at all - see
# _GLB_PACKAGE_MANUAL_HINT in lib/package.sh, which now surfaces this
# explanation (and the fix command) at the manual-step pause instead
# of just re-showing a `sudo apt install -y snapd` that would fail
# identically every time. yazi below fails as a direct consequence on
# Mint until snapd is manually unblocked.
snapd

# CPU architecture info banner (James Tigert / kz6fittycent), pairs
# with fastfetch above. A real native package on all four managers -
# no per-distro override needed, name is "cpufetch" everywhere.
# Confirmed current (1.07, matching upstream) on Fedora 44+ (dnf),
# Arch's `extra` repo (pacman), and openSUSE Tumbleweed (zypper).
# Debian stable/trixie lags one point release behind (1.06-2) - a
# real but minor gap, not worth a workaround; same tolerance as every
# other "not quite latest" package GLB installs via the system package
# manager. Originally added via the `snap` method (2026-08-17) before
# checking whether a native package existed on every distro - switched
# to a plain package once it turned out one does, avoiding an
# unnecessary snapd dependency and the manual-step pause that would
# have caused where snapd itself is a known gap (see snapd's own
# comment above).
cpufetch

# Not in apt's index on every distro (e.g. not packaged on this Pop!_OS
# setup, nor on Linux Mint 22.3 - confirmed 2026-08-07, reconfirmed on a
# fresh Mint VM 2026-08-25, same "has no installation candidate" error)
# — may need a PPA or manual install. No known curl-install script to
# move this to extras.txt like fresh; it's a repo-availability gap, not
# a wrong-install-method one. Not worth chasing further: Mint already
# ships `neofetch` preinstalled, which covers the same "system info
# banner" niche well enough there (even though neofetch itself is
# archived/unmaintained upstream - not worth adding as a real
# cross-distro fallback for fastfetch, just a happy coincidence on Mint
# specifically).
fastfetch
